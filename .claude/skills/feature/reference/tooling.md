# Existing debug & QA tooling (what to reuse in Step 0)

Verified against the tree on 2026-08-26. Re-check paths before relying on them; if something moved, fix this file.

## Client (`cmd/client`)

| Flag / key | What | Where |
|------------|------|-------|
| `--config config.yaml` | GRF paths, server, test account (`midgard-test`) | `internal/config/` |
| `--debug` | debug log level + FPS | `internal/config/flags.go` |
| `--trace=move,pick,net,render` or `all` | opt-in per-subsystem tracing at info level; free when off | `internal/trace/trace.go` |
| `--screenshot-after 8s` | one unattended capture after startup, then keeps running | `internal/game/game.go` (`checkTimedScreenshot`) |
| `--screenshot-every 5s` | repeating capture | same |
| `--width/--height/--windowed` | window size | `flags.go` |
| **F12** | manual screenshot | `game.go` |
| **F3** | debug overlay (player, camera, scene FB, GL error, terrain Y, packet stats) | `internal/game/ui/debug_overlay.go`, `internal/game/debug_fields.go` |
| **F4** | hide map objects (terrain only) | `game.go` |

Screenshots land in `data/Screenshots/` (`screenshot-YYYYMMDD-HHMMSS.png` + `latest.png`). `data/` is gitignored — copy what you need into `docs/features/<slug>/`.

Typical unattended run (server must be up):

```bash
make server-up
go run ./cmd/client --config config.yaml --trace=move,net --screenshot-after 8s 2>&1 | tee "$SCRATCH/run.log"
# in another shell, or after Ctrl-C:
pkill -f "cmd/client|/midgard$"
```

### Adding a trace channel

`internal/trace/trace.go`: add a `const <Name> = "<name>"` next to `Move/Pick/Net/Render`, then in the hot path:

```go
if trace.On(trace.Entity) {            // guard only when fields are expensive
    trace.Emit(trace.Entity, "entity.spawn", zap.Uint32("id", id), zap.String("kind", kind))
}
```

Event names are `<channel>.<verb>` so a trace reads as a pipeline. Keep channels coarse — one per subsystem you would debug as a unit.

### Adding F3 fields

Add the field to `DebugOverlay` in `internal/game/ui/debug_overlay.go`, populate it in `populateDebugFields` (`internal/game/debug_fields.go`), render it in the overlay's draw function. Populate every frame; the overlay only draws when F3 is on.

## grfbrowser (`cmd/grfbrowser`)

```bash
go run ./cmd/grfbrowser --grf "$GRF"                 # browse
go run ./cmd/grfbrowser --grf "$GRF" --map prontera  # auto-load a map
```

- Previews: sprite/ACT playback (`preview_sprite.go`), images (`preview_image.go`), RSM models (`preview_model.go`, `model_viewer.go`), maps (`preview_map.go`, `map_viewer.go`), WAV (`preview_audio.go`). Properties panel shows parsed metadata — RSM node transforms, animation flags, etc.
- **F12** → `/tmp/grfbrowser/latest.png`; a `state.json` dump lives beside it (`commands.go`, ADR-010 Phase 2). The `Command` struct for remote automation exists (Phase 3) — check `commands.go` for what is actually wired before depending on it.
- Rendering pipeline is shared with the client (`internal/engine/*`). PR #78 removed a third copy of the sprite pipeline — do not plan another.

## Lessons the tooling already taught (from PR #78 / e76cf49 / ADR-014)

- Missing assets must log at warn with the path — a swallowed error hid a black login screen.
- Measure before tuning: the prediction tolerance came from 85 logged acknowledgements, not a guess.
- Keep debug info after the bug is fixed — the RSM properties panel paid for itself twice.
- Packet framing bugs look like feature bugs; trace `net` first when anything server-driven misbehaves.
