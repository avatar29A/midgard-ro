How a command reaches the server

Three rules, and they are not symmetric. This is the thing to know before reading any table below.

@ and # are ordinary chat

There is no command packet. The client sends a normal CZ_REQUEST_CHAT (0x00F3) and the server pulls the command out before broadcasting.

clif.cpp:10554 — is_atcommand()

/ never reaches the server

Nothing server-side parses a leading slash. The client answers locally, or sends a dedicated packet that the server converts back into an at-command.

clif.cpp:11558 — /mm becomes @mapmove

The sigils are configurable

@ and # are atcommand_symbol and charcommand_symbol, settable per server. Ours are the defaults.

atcommand.cpp:89-90

Two consequences worth remembering. A command sent as a whisper is never seen — only the public-chat path checks for commands. And a command you are not allowed to use gets broadcast: the group check fails, the line carries on as ordinary speech, and a normal player typing @mapmove prontera 100 100 shouts it at the whole map. Both are the original's behaviour, not bugs.

Things that will bite

Each one verified against the server tree rather than assumed.

0x02C1 carries BGR, not RGB

rAthena's colour table is byte-swapped once at startup and then sent unswapped, so the wire value is already BGR. Reading it as RGB turns light green 0xB5FFB5 into a light pink. Used by @rates, @mobinfo, @iteminfo — 7 call sites against 1035 for the plain path.

0x009A encodes its colour as literal text

A broadcast beginning "blue" renders blue, "ssss" gives the WoE style, anything else is yellow. Strip the prefix, or @kamib hi renders as bluehi.

Command replies are green, not yellow

Every at-command answers on ZC_NOTIFY_PLAYERCHAT 0x008E, which the original paints green — it maps to PUBLIC|SELF. Our client currently paints these yellow.

/item is 0x09CE, 102 bytes

Not the 0x013F/26 that the base block registers. 0x09CE is added for PACKETVER >= 20131223 and ours is 20211103. Likewise /resetskill does not use 0x0BB1: that registration is guarded on MAIN/ZERO packetvers and we are RE.

@commands output will not line up

The server pads names into 10-character columns with spaces, assuming a fixed-width font. Ours is Arial Unicode, so the list renders ragged. Cosmetic — not a defect.
